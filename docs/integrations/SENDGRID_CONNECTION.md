# SendGrid connection

The Communication page provides admin-only configuration of a SendGrid API key and sender. Settings are encrypted using the existing `INTEGRATION_ENCRYPTION_KEY`, stored outside the source tree in the absolute `SENDGRID_CONFIG_DIR`, and never returned to the browser. The parent of this directory must be a dedicated persistent writable volume; the application creates the private child directory with mode 0700 and files with mode 0600. Provisioning this storage does not require a schema migration. Do not rotate or expose the shared encryption key.

Configuration and removal require `configuration.manage`, a same-origin request and a matching revision. Simultaneous edits are locked. Removing the saved connection does not revoke the key at SendGrid; revoke it separately. A connection test sends a GET only to `https://api.sendgrid.com/v3/scopes`, with redirects disabled, and reports whether `mail.send` is listed. It does not send an email, verify the sender/domain, or prove deliverability. Failed/unauthorized results do not expose provider bodies or keys. The API scopes behavior is documented in SendGrid's official API specification: https://github.com/twilio/sendgrid-oai/blob/main/spec/json/tsg_scopes_v3.json.

An administrator can explicitly confirm a single test email to a chosen recipient. A persistent request claim prevents automatic retries and duplicate requests; an uncertain result must be investigated before another test. SendGrid acceptance does not confirm delivery. Campaigns, templates, event webhooks, suppression and unsubscribe handling are not implemented. Use synthetic keys and mock provider responses for development; revoke the key exposed in chat and enter a new one directly into the secure UI.
