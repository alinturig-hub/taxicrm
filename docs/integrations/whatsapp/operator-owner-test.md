# Owner-only operator reply test

This feature is disabled by default; deploying it does not enable takeover or sending. A later reviewed test can set `WHATSAPP_OPERATOR_OWNER_TEST_MODE=true` with an E.164 `WHATSAPP_OPERATOR_OWNER_TEST_RECIPIENT`, a unique random `WHATSAPP_OPERATOR_OWNER_TEST_ID` (16–80 letters, digits, `_` or `-`), the lowercase SHA-256 of the exact approved UTF-8 text in `WHATSAPP_OPERATOR_OWNER_TEST_BODY_SHA256`, and a UTC ISO timestamp `WHATSAPP_OPERATOR_OWNER_TEST_EXPIRES_AT` no more than 24 hours in the future. The test's other sender flags `WHATSAPP_JOURNEY_SENDING_ENABLED` and `META_WHATSAPP_TEST_SEND_ENABLED` must both be explicitly `false`. All normal controls and Meta sending flags remain disabled unless separately authorized.

The gateway checks the participant and exact approved text while holding the conversation lock. Owner-test mode also guards the legacy CRM handoff entrypoint. A fixed durable operation key derived from the test ID permits at most one provider attempt, including concurrent distinct commands or a process restart. Changed payloads conflict; UNKNOWN/SENDING is never retried. An 8-second expiry margin and the existing 24-hour, suppression and revision checks remain in force. A release is permitted for the allowlisted conversation after test expiry or if other sender flags change, provided operator controls remain enabled. Release the conversation before disabling operator controls.

The owner-test mode setting is deliberately required for operator controls to be enabled: use explicit `false` only for a separately approved unrestricted rollout. Missing, invalid or incomplete test configuration fails closed. The old CRM handoff entrypoint retains its pre-existing behavior when test mode is absent or false. During a test, never rotate the test ID to repeat an uncertain operation; review the existing outbox record and provider status first. The test ID must be new for each separately approved test. No schema or grant changes are included.

A separate NeedACab Plus change displays when an accepted request reused an existing operation; it must not claim that a second message was sent. This mode does not establish opt-in or an open 24-hour service window, and it does not configure or send any message by itself.

The configured hash pins the text used by this process; it is not an independently signed approval or proof of the recipient's identity. Prepare and review the exact message and a new test ID before any production configuration, and prevent configuration changes while the test is in flight. Verify every active CRM replica runs this guarded version with identical test configuration before enabling send; an older instance would not enforce this guard.
