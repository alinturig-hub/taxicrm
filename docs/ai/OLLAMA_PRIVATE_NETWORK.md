# Local Ollama over a private container network

The owner agent accepts an Ollama URL only when its exact origin is listed by an administrator in `TAXICRM_AGENT_OLLAMA_ORIGINS`. HTTPS remains supported. HTTP is limited to loopback or an RFC1918 IPv4 literal; hostnames, public and link-local addresses over HTTP are rejected, even if listed. Credentials in URLs, alternate paths, query strings and redirects are not accepted. The allowlist is checked both when settings are saved and when a model is called. Removing an origin blocks later use.

For the observed deployment, the host gateway was `10.0.1.1` and a read-only `/api/tags` probe from the TaxiCRM container succeeded. An administrator can configure the exact origin `http://10.0.1.1:11434` if that private network remains under their control. The gateway may change after network recreation. HTTP on the bridge is not encrypted or authenticated; the operator must restrict access to Ollama at the network/firewall layer and must not expose it publicly. Model availability, resources, permissions and inference latency must be tested separately. No model download or live inference was performed by this change.

The configured model receives the question and approved objective preferences, but not raw database records. Questions can contain information typed by the user. It selects an allowlisted analysis; numbers and proposals are generated by deterministic code. This change neither enables the agent nor supplies the required read-only database binding, confirmed company scope or private durable memory.

The explicitly configured Ollama provider uses the native `/api/chat` endpoint with `think: false`, JSON output and a bounded 80-token answer, because the tested `qwen3:30b-a3b` OpenAI-compatible endpoint returned only reasoning and an empty answer at that limit. Invalid, empty, oversized or tool-call outputs use the deterministic fallback. The Ollama server/model must support the native `think` option; validate the actual installation before relying on it. Gateways returning 404 or 405 for the native endpoint fall back once to the existing OpenAI-compatible API on the same allowlisted origin; the fallback may still return an empty response for reasoning models. Other providers retain their existing API formats.
