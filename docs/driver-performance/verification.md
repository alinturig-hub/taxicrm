# Driver performance initial slice verification

The first slice adds London-day login/logout sessions to the existing driver profile and metered miles for positive metre readings on completed bookings, matched to both driver identifier and provider. It reports the number of completed bookings with positive, zero/missing/invalid readings. The metric uses scheduled pickup date and is not total mileage or accepted-to-completed GPS mileage. Zero is not asserted to be missing or a confirmed driven distance.

Authenticated browser and API tests used a dedicated local PostgreSQL container with synthetic users, drivers, shifts and bookings. They verified the driver-provider collision, zero reading and cancellation exclusion; overlapping sessions; incomplete logout; refresh; invalid date; unauthenticated denial; an authenticated role lacking drivers.view (the new metric is absent and the sessions API denied while existing API output remains available); mobile horizontal fit; and unchanged booking rows. Synthetic unit tests covered metre conversion, zero/null, London DST and rejection event deduplication. TypeScript, ESLint and production build passed.

Production source coverage was inspected separately with the existing `cabby_ro` role and aggregate queries; see initial-assessment.md. The release introduces no schema, worker, ingestion, message or configuration changes. A genuine authenticated production interaction is not claimed from synthetic tests.

Known limitations: the profile is a first slice; it does not calculate GPS total/on-job/empty miles, breaks, price at refusal, reasons for rejection, per-hour rates or a predictive driver score. The existing driver profile's other analytics have their prior definitions and are not validated by this slice. Login/logout events depend on source completeness; an open session or 200-row limit yields an unavailable total rather than an asserted duration. A future or invalid source timestamp may need further data-quality treatment.
