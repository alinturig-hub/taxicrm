# One-time owner campaign test

The temporary test is opt-in and limited by `EMAIL_OWNER_TEST_ENABLED`, a fixed `EMAIL_OWNER_TEST_RECIPIENT`, a random `EMAIL_OWNER_TEST_NONCE` and `EMAIL_OWNER_TEST_EXPIRES_AT` (no more than 24 hours in the future). General campaign sending must be disabled. A user with `configuration.manage` sees the sender, recipient, subject and body and explicitly confirms one real email. The content is fixed in code; the dispatcher appends the unsubscribe link.

Before any provider call, one durable database event claims the nonce. A transaction creates one test campaign and one recipient in `PAUSED` status; normal scheduled workers cannot select it. The activation route blocks owner-test campaigns. The dispatcher targets that exact campaign, checks suppression and sender, makes at most one provider POST, and never retries an ambiguous outcome. A process crash after the claim cannot be safely retried with that nonce. The owner test is separate from any previously scheduled campaign. Inspect provider activity and history if the result is unknown. Only ACCEPTED means provider acceptance, not delivery.

Synthetic PostgreSQL tests cover concurrency, duplicate requests, unknown responses and unrelated scheduled campaigns; browser tests cover confirmation and cancellation. Configure the one-time nonce and recipient privately; never place API keys in this file or logs. Production sending is not enabled by this feature. After completion or expiry, remove/disable the test configuration; do not rotate the unsubscribe secret casually because existing links depend on it.
